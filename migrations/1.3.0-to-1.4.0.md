# Migrating from REOP 1.3.0 to 1.4.0

1.4.0 is a minor release: every valid 1.3.0 document is accepted by a 1.4.0 reader after the rules below are applied, and no member was removed. Producers SHOULD emit the 1.4.0 forms; deprecated forms stay valid until 2.0.

## Compatibility promise

- A consumer of 1.4.0 MUST accept any `1.x` document: lower minors through these upgrade rules, higher minors by preserving and ignoring unknown members.
- `protocol.version` is required from 1.4.0 on. A document without it is treated as 1.3.0 or earlier and upgraded.
- Deprecated members are marked `deprecated: true` with `x-replacedBy` in the schema; they are removed only in a major release.
- Unknown properties MUST be preserved by intermediaries. Vendor data belongs under `extensions`.

## Upgrade rules (1.3.0 document -> 1.4.0 document)

Apply in order; every rule is idempotent.

| # | 1.3.0 | 1.4.0 | Rule |
|---|---|---|---|
| 1 | missing `protocol` | `protocol { name: "REOP", version: "1.4.0" }` | add; set `generatedAt` and `generator` if known |
| 2 | `protocol.domain` | `protocol.generator` | copy when `generator` is absent; keep `domain` (deprecated) or drop it |
| 3 | `marketing.logo { square, landscape }` | `marketing.logo { url }` | `url = square`, else `landscape`; drop the pair |
| 4 | `marketing.gallery[] { type, url }` | `MediaAsset` | nothing to do; `type` defaults to `image` |
| 5 | `marketing.layoutImage` | `marketing.floorPlans[0] { url, role: "plan" }` (project: `role: "sitePlan"`) | move; infer `format` from the URL extension when obvious |
| 6 | `marketing.blueprint` | `marketing.floorPlans[] { url, role: "blueprint" }` | append |
| 7 | `unitModels[].marketing.heroImage` with no gallery | `gallery: [{ url: heroImage }]` | optional convenience; `heroImage` stays |
| 8 | `paymentPlan.installments[].phase` (key) | unchanged | nothing to do; add `title` when a human label is known |
| 9 | `amenities[].name` not in `vocabularies/amenities.json` | `+ label` | a custom amenity needs a localized `label`; derive it from the key when nothing better exists |
| 10 | `Money.currency` | unchanged | any ISO 4217 code is now valid |
| 11 | `inventory[].status` | unchanged | the 1.3.0 values are unchanged; `onHold` and `booked` are new |
| 12 | `Floor.number` | required | add the number when the 1.3.0 producer omitted it (the YAML required it; the JSON Schema did not) |
| 13 | `unitModels[].specs.bedrooms` | unchanged | an external 1.3.0 document means bedrooms literally; do not derive `rooms` |

Members deprecated on a given entity (for example `startingPrice` on a developer, `social` on a unit model) stay where they are; readers ignore them.

## Rooms and bedrooms

`specs.rooms` (advertised habitable rooms, market convention) and `specs.bedrooms` (separate sleeping rooms) are independent facts. Store what the source states; never compute one from the other for storage. A consumer that must present the other convention may derive a display value (for example `bedrooms + 1` in a market that counts the living room) but must not write it back. The conventions per market are documented in `vocabularies/roomCountConventions.json`.

A producer whose own 1.3.0 documents carried the advertised room count in `bedrooms` (a known practice in rooms-convention markets) migrates its own data by moving that value to `rooms`; this is a producer-specific correction, not a protocol rule.

## Availability

`unitModels[].availability` summarises inventory: with `A` = units of the type whose status is `available`, the value is `sold_out` when `A = 0`, `last_units` when `A` is small (operator threshold), `available` otherwise. Units that are `onHold`, `reserved`, `booked`, `sold` or `notForSale` never count. A producer without inventory may state the value directly.

## Consumer checklist

- Read `protocol.version`; reject other majors, upgrade lower minors, tolerate higher minors.
- Read `marketing.logo.url`; fall back to `logo.square` / `logo.landscape` for old producers.
- Read `floorPlans[]`; fall back to `layoutImage` / `blueprint`.
- Treat gallery items as `MediaAsset`; use `previewUrl` for videos and documents.
- Resolve amenity keys through `vocabularies/amenities.json`; show `label` for custom keys.
- Validate inventory links (`links.modelId` must exist) before trusting availability.
- Keep unknown members when re-emitting a document.

## Producer checklist

- Emit `protocol { name, version: "1.4.0", generatedAt, generator }`.
- Emit `logo { url }`, `floorPlans[]`, `experiences[]`, `documents[]` instead of the deprecated members.
- Emit `rooms` and / or `bedrooms` as stated by your source; never both from one number.
- Give every unit model, building, floor, unit and interest a stable `id`.
- Put vendor data under `extensions.<vendor>`.
